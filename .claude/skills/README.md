# Skills index — everything we've already built

This is the **canonical list of every Claude skill in this repo**. Its job is to answer,
at a glance, *"do we already have a skill for this?"* — so we **feed and improve** an
existing skill instead of quietly building a second one that does the same thing.

**How to use it**
- Ask any session *"¿tenemos un skill para X?" / "what skills do we have?"* and it answers
  from this list.
- Before proposing or creating a **new** skill, a session checks here first. If one already
  covers the topic, it says so plainly — *"ya tenemos un skill para eso"* — and offers to
  **enrich that skill** with the new information rather than duplicate it.
- When a conversation surfaces a rule, preference, or lesson that belongs in an existing
  skill, that's a cue to update the skill (each skill ends with an "update this skill when…"
  note).

Each skill lives in `.claude/skills/<name>/SKILL.md`; open that file for the full detail.
The one-liners below are just the "when to reach for it."

| [`tax-return-sop`](./tax-return-sop/) | 🔴 **PREPARING A CLIENT'S RETURN — load it on *"prepárame el Tax Return de X cliente"* / *"prepare X's tax return"*.** §4A runs **TWO PHASES from one sentence**: 🔍 **Fase 1 · la Revisión** — [`organizer-review`](./organizer-review/) in full, **always**, whose Block A verdict is ⚖️ **the gate** — then 🧮 **Fase 2 · la Preparación**, the tables, **only if the gate says yes**. Also writing/extending a **TAX-RETURN SOP** — the form-by-form procedure for one kind of return (`form-1120s-preparation.md` is the reference; one per form is the goal) — **and using one to drive a real return**, producing the line-by-line tables a first-time preparer can work from. Why these differ from every other SOP (they must say *where each number comes from*), the required spine, build-the-map-from-the-prior-year, the **fifteen-part delivery standard** — ten headline parts and five sub-parts *(distributions-vs-basis · the reconciling schedules · the software's figure wins · the basis grid · the click path, not just the field name)* — (a table per form · the order of preparation · the flow of figures between forms · the checkboxes with their reasons · the explanations · **the statements and attachments the return requires, drafted** · **every K-1 box by box** · 🛠️ **the ENTRY ROUTE — where each figure is actually TYPED**, which is usually not the form it appears on · 🛑 **every finding delivered WITH ITS FIX** — where, what to type, how to know it worked, what it moves · 🔗 **ONE RETURN PER REQUEST**, the company ending in a **handoff** to the owner's 1040 rather than in the owner's return), all written for **someone who knows nothing about taxes or forms**, the 🛑 **pull-the-PDF-from-irs.gov** rule for any answer that changes a figure, and the working paper every return leaves behind. 🔵 **AND §4C — THE OTHER DIRECTION: a return the firm prepared coming back to be REVIEWED.** **Someone** — in practice Julia — brings it back and starts asking — the financials, **or** the return, **or** just a question about a line, **any one of which is the trigger**; the job is to **brief her from the working paper before opening the PDF** — the reason before the finding, every figure with its source, and the three-way split **decision · open item · defect**, because they read identically on the return and need different answers. 🔑 **A decision that makes the return WRONG is still a defect** — the label follows the correctness, not who chose it.
